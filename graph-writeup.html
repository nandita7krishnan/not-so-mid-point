The Not-So-Mid-Point Graph

An agent that finds a meeting spot two to five people can each reach fairly, by asking Google what transit actually costs instead of averaging coordinates. Six supersteps, one of which fans out five ways.

11 nodes 15 edges 6 supersteps 3 reduced channels StateGraph over a TypedDict

The shape

The problem decomposes cleanly: narrow the map once, measure each person's trip independently, then collapse the measurements into a single ranking. Only the middle step is per-person, and it is the step that dominates latency — every candidate neighbourhood costs one routing call per traveller. So the graph is a straight spine with exactly one parallel band in it.

#NodeExternal calls (P = party size)Writes
1 node0_search_area P Distance Matrix requests, each covering ≤ 16 corridor candidates at once search_area
2 reach_person1…5 P × 8 Directions requests, all in flight together behind a 12-permit semaphore reachability[i]
3 nodeC_shortlist none — pure computation over what the band collected shortlisted_neighbourhoods
4 nodeD_spots ≤ 5 neighbourhoods × up to 2 Places queries, plus ≤ 2 LLM calls preference_spec, candidate_venues
5 nodeE_score none ranked_venues
6 nodeF_review ≤ 3 concurrent LLM calls, one per surviving pick final_top_3

Every node also merges one key into timings, so a finished run carries its own profile. With five people, superstep 2 alone issues forty routing requests; serialised, that is the whole latency budget.

Channels and reducers

State is a plain TypedDict of pydantic models. Most keys are written by exactly one node and need no reducer — last writer wins because there is only ever one writer. Three keys are different: they are written inside the parallel band, or by every node in the graph.

ChannelTypeReducerWhy
reachability dict[int, list[Leg]] operator.or_ Five nodes write in the same superstep, each under its own integer key. Dict union merges them without any node needing to know the others exist.
warnings list[str] operator.add Any node may append a caveat — dropped candidates, an LLM that fell back. Concatenation keeps them all.
timings dict[str, float] operator.or_ Every node stamps its own duration under its own key, including the five that run concurrently.

Static slots instead of dynamic fan-out

The party size is a runtime input between two and five, so the obvious implementations are a loop inside one node, or LangGraph's Send API to spawn one branch per person. The graph does neither: it declares five nodes at build time and lets the unused ones no-op.

  • A loop inside a single node would still be concurrent — it is asyncio.gather either way — but the graph would no longer say so. The topology is the documentation, and a five-way fan-out that only exists inside a function body is invisible to anything that reads the compiled graph: the trace, the visualiser, the blog post.
  • Static nodes keep per-person timings and per-person failures attributable, because each slot writes its own channel key and its own timings entry.
  • The cost of the unused slots is a dictionary lookup: the node returns {} before it constructs a client or touches the network.
  • The ceiling is a real constraint, not laziness. Five is where the transit corridor stops being a meaningful shape and the per-search API bill stops being comfortable, so bounding the fan-out at build time bounds the spend too.
The trade: Send would scale to an unbounded party at the price of a topology that cannot be drawn until runtime. With a hard upper bound of five, the static version buys legibility for nothing.

Failure is a channel, not an edge

Nothing in the graph branches. There are no conditional edges and no early exit — when a node cannot continue, it writes a GraphFailure into the failure channel and returns. Every downstream node opens with the same two lines:

if state.get("failure"):
    return {}          # the run continues; this node just has nothing to add

The source

Two artefacts worth lifting straight into a post: the builder, and the Mermaid that LangGraph emits from the compiled graph.

def build_graph():
    graph = StateGraph(MeetingState)
    graph.add_node("node0_search_area", search_area_node)
    for index, node in enumerate(REACHABILITY_NODES):
        graph.add_node(f"reach_person{index + 1}", node)
    graph.add_node("nodeC_shortlist", shortlist_node)
    graph.add_node("nodeD_spots", spot_finder_node)
    graph.add_node("nodeE_score", scorer_node)
    graph.add_node("nodeF_review", reviewer_node)

    graph.add_edge(START, "node0_search_area")
    # Every reachability node hangs off Node 0 and feeds the same fan-in,
    # so they all execute in one superstep.
    for index in range(len(REACHABILITY_NODES)):
        graph.add_edge("node0_search_area", f"reach_person{index + 1}")
        graph.add_edge(f"reach_person{index + 1}", "nodeC_shortlist")
    graph.add_edge("nodeC_shortlist", "nodeD_spots")
    graph.add_edge("nodeD_spots", "nodeE_score")
    graph.add_edge("nodeE_score", "nodeF_review")
    graph.add_edge("nodeF_review", END)
    return graph.compile()
